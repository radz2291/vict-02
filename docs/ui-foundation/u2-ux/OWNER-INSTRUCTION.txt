3. Deliver usable Inspector and Layers modules.

Inspector:
- A clear selection header with a meaningful name and breadcrumb.
- Clear scope: this instance versus the shared component, including the number affected where known.
- Organized Content, Style and Behavior sections.
- Common controls for text, text/background color, typography, dimensions, spacing, layout and borders.
- Appropriate controls: color swatches/picker, numeric values with units, choices and alignment controls.
- Populate controls from the selected source and available effective values.
- Explain inherited/shared/local/condition values accurately, with Override and Reset where supported.
- Make the active condition and pseudo state understandable.
- Offer declared actions through a picker; support friendly labels without inventing product semantics.
- Keep raw CSS declarations, attributes, bindings and source identifiers available through Advanced.
- Provide useful empty, disabled and error states.

Layers:
- A readable hierarchy with clear expand/collapse affordances.
- Meaningful names derived from source metadata, roles or content, with sensible generic fallbacks.
- Clear selection synchronized with the canvas.
- Components and their internal structure organized so the default view remains scannable.
- Keyboard navigation, visible focus and usable scrolling.
- Preserve definition, instance and repeat provenance; deeper technical details remain accessible.

Do not hardcode Northwind-specific identifiers or labels inside the reusable toolkit. Label resolution may use compatible optional host metadata.
