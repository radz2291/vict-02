# Five-task founder observation

Status: prepared, participant observation pending. No human acceptance or task timings have been claimed.

Use a disposable browser profile against /editor-review. Keep the original saved fixture intact in the owner's normal profile. Allow five to ten minutes; give only the task wording below. Do not explain where controls are. Record a participant's words only with their permission.

1. Make the large heading say something of your choosing, and make it slightly larger.
2. Give all service cards a new background color, then make the first card different. Explain which cards will change before each edit.
3. Add equal space inside a card on all four sides. Undo the change, then bring it back.
4. Find the card description through Layers. Change its inherited text color, then return it to its original appearance.
5. Save, reload and confirm your work survived. Try editing with a narrow window; find text size again.

For each task record: first control chosen, hesitation or backtracking, whether help was required, accidental shared changes, whether the participant correctly described the effect, and completion. Afterward ask: "Which control was hardest to understand?" and "What did you expect to happen that did not happen?"

Suggested acceptance questions: can the founder predict scope, distinguish a source value from a current browser result, recover with Undo/Reset, and return to the selected object without assistance? Use observed failures to set the next iteration priorities. This is a prepared exercise, not a passed acceptance gate.
