## Storage and transaction design

The version-2 operator fixture adds six relations to the base schema. Slot requests reserve a per-turn ordinal and allocation atomically. Invocation rows index ID, request key and turn. Approval rows preserve history, select the latest row for an invocation and have a partial pending index. Command rows index the exact legacy composite key and earliest surviving insertion by actor/key. Confirmation rows index ID, both list scopes and replacement order. Secondary filters check their own tuple fields, keeping the legacy equality semantics. Identity queries resolve a digest bucket and compare the full UTF-16 bytes. Lexical queries sort by prefix and then full bytes, preserving JavaScript order even for long shared prefixes. [DDL](vhost-003-candidate/receipts-schema.sql)

Each normal call admits the namespace/epoch in one PostgreSQL transaction, checks any scope lease on that client before and after work and loads only the exact rows needed. Mutations take transaction advisory locks ordered by their actual lock identifiers, including across invocation ID/request, approval ID/invocation and slot/turn-head identities. A collision can serialize unrelated work. Full key comparison decides equality. Existing mutable rows are locked for state transitions. The pinned Runtime transition is applied to a bounded local row set, usually one row and at most two for the conflicting creation identities. Insert or update writes only the changed row and its required metadata. Allocating a slot without a later invocation retains the slot. List results use the named relations and transaction-local cursor where needed. The fixture trusts its single admitted storage implementation to preserve full-key uniqueness under those locks. Release integration must enforce the writer policy and evacuate incompatible legacy writers before import. ## Decisions and release blockers

- **D5 approved strict digest rule.** Radzi ruled that a conflicting prepared operation digest must fail closed inside the transaction that would publish, select and advance the receipt. The pinned PostgreSQL adapter still applies the mismatching operation. The SQLite reference rejects it with `VICT_CONTROL_OPERATION_IDENTITY_CONFLICT`; the new guard verifies the release, current selection, selection list and prepared receipt remain deep-equal to their earlier values. The runner records indexed control as absent and automatically exercises the guard when that port is later present. The authorized control slice must add concurrency and a positive same-digest install/replay case and prove the comparison and mutations are atomic.
- **D6 approved conservative callback admission.** Preserve the namespace callback-admission mutex and C12 two-scope same-client assertions. The installed native-thread-recoverable journal is rerun with the pinned C12 packages. The contention fixture is local and deliberately injects time under the mutex. It supplies no hosted capacity target.
- **Coordination text key compatibility.** In the pinned driver, a lone surrogate and the replacement code point can hit the same legacy PostgreSQL text key. The private fixture rejects malformed UTF-16 coordination inputs. A package decision is outstanding on input rejection versus lossless coordination keys and migration of historical aliases.
- **Command claim fences across release and recreation.** Both reference and candidate reissue the same token when a valid release is followed by a fresh claim of the same key, owner and attempt number. Since token equality is the settlement authority, these two logical claims cannot be distinguished by the port. Expired-lease takeover advances the claimed generation and passes the stale-token checks. Until a takeover or terminal transition occurs, the port continues to honor the current token. Before serving, the owner needs to approve a non-repeating claim identity, such as a unique owner per claim or an agreed persistent generation across release, and qualify legacy callers against it.
- **Service policy dependencies.** Direct-port conflicts preserve the legacy results. The command service owns digest comparison and cross-command reuse policy, confirmation scope and actor checks, and stale subject checking. The source currently composes the cross-command read and command-specific claim as separate calls. Simultaneous different-command reuse needs an independent policy check before a package can claim exclusivity across command kinds. Approval wall-clock eligibility also belongs to service logic. The legacy slot and command ports construct composite Map keys with separators. The fixture mirrors those exact key semantics pending public key-domain and migration review.
