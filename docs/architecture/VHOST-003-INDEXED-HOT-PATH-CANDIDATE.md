# VHOST-003 review

VHOST-003 delivers a test-only indexed PostgreSQL candidate for actors, agent turns and Stop, the stream ledger, and scoped coordination. It exercised 34 qualified operations, including the partial leased facade and disposal. The other 92 legacy operations are absent from the fixture. The branch has no package export, dependency changes, deployment, production migration, Quellight changes or Gate A/B verdict. [Port coverage and completion dependencies](vhost-003-candidate/PORT-COVERAGE.md)

## Foundation and correctness

- The operator provisions a fixed, versioned fixture schema. Every candidate transaction checks the marker and writer epoch under a shared row lock. Epoch advancement waits for in-flight transactions, then retires existing lease generations without removing tombstones or effect receipts. Reopening with the new epoch still refuses the old lease. A new lease can use the same scope and observe retained receipts. This is an epoch rehearsal inside the fixture.
- The candidate reuses the pinned driver for bounded pool checkout, lock and statement timeouts, rollback, close and sanitized errors. It adds an overall PostgreSQL transaction timeout. Scope checks reject an outside client, a foreign candidate, and an expired or forged resource generation. Trusted callbacks acquire the callback admission row before scope locks. Ordinary leased operations lock their primary scope and then their own aggregate. The candidate holds the same client and rechecks the lease after the operation.
- Actors and streams have indexed exact keys. Turns and cancellation use a digest bucket with full UTF-16BE comparison and indexed sort prefixes. The aggregate guard serializes a colliding bucket without making a digest the authority for equality. The pinned tagged codec preserves property order, explicit undefined and exact UTF-16 values for turn and stream records. Actor upsert separately preserves the legacy per-record JSONB normalization, including its rejection of embedded NUL. Stream clock and event writes are atomic, and a cursor sees one PostgreSQL snapshot across bounded SQL fetches. No operation reads or rewrites the legacy snapshot.
- The 79 differential calls compare all 20 actor, turn, Stop and stream methods with the installed PostgreSQL adapter, including exact safe errors, unchanged intent replay, invalid transitions, ordering, cancellation before the turn exists, and cursor edge cases. Concurrent checks admitted one of 20 duplicate cancels and one of 12 competing turn starts. The stream allocated a contiguous sequence across concurrent durable and transient appends, retained 145 durable events, and preserved the read view when another client appended between cursor pages.
- The compatibility layer preserves caller-supplied actor semantics on the neutral ports. Tenant segregation is by namespace, coordination binds an actor to its scope, and Quellight continues to own application authorization. The candidate refuses malformed text identifiers after reproducing that legacy PostgreSQL aliases a lone surrogate and U+FFFD in a coordination scope. Turn record and cancellation keys use binary encoding and can keep distinct opaque identities. The coordination refusal applies only to the test fixture. A public rule or a lossless coordination-key format needs a separate approval.
- The exact installed C12 `native-thread-recoverable` adapter completed four two-fence journal transactions with both leases checked on the same PostgreSQL backend. It reopened its distinct memory schema under the matching operational marker and rejected the wrong namespace. A separate synthetic callback verified rollback after a thrown callback or stale resource lease. The held pool and scope rows returned sanitized errors at 122 ms and 130 ms respectively, and both paths recovered. The tests use a fixture operator role, so they do not qualify a least-privilege serving role or external pooler.

## Matched results

Both implementations completed 648 timed operations across 27 cells each, with zero unexpected outcomes. They used the same 200, 1,050 and 2,950 unrelated-stream histories. Legacy seed snapshots measured 110,635, 563,685 and 1,576,385 bytes before database JSONB formatting. The final fixture required the raised legacy node cap for timing. The candidate used the default per-record cap.

Candidate median inbound bytes per operation stayed constant across all three populations. Query plans show a bitmap index path for the stream range and a primary-key arbiter for appends. PostgreSQL chose scans of tiny turn and cancellation relations in these fixtures. PostgreSQL WAL for the largest four-connection append cell was about 5.72 MB legacy and 28.4 kB candidate. Instrumented Node CPU was about 4.88 s and 0.094 s for that cell. Those are whole-cell observations and include measurement overhead.

Candidate latency varied across runs. Its slowest observe p95 was 610 ms with eight clients sharing one connection, with a 528 ms pool-acquisition p95 and sampled WAL writes. The large four-connection Stop p95 was 282 ms in the final run and 34 ms in the earlier iteration. This supports a byte-scaling finding. It leaves representative latency, lock-tail, capacity and cost targets open. Measurements use short closed-loop samples, shared workstation and loopback without TLS. They do not establish hosting egress, production capacity, database process CPU/RSS, remote latency, or a user-facing Stop target.

D6 used eight callbacks with four clients and opposite thread/resource acquisition orders. The namespace callback lock serialized them with observed transaction/tuple waits and no deadlock. With an injected 35 ms hold, callback p50/p95/p99 were 198/258/258 ms. An unrelated leased Stop completed in about 10 ms while a callback held both of its own scopes. Keep this conservative default for the next slice and measure the queue under representative C12 traffic before changing the admission contract.

## D5 decision

The same prepared operation carried `prepared-digest` in both stores and was applied with `different-digest`. Legacy PostgreSQL returned selection revision 1, published and selected the release, and marked the existing receipt applied with its original digest. The SQLite adapter returned `VICT_CONTROL_OPERATION_IDENTITY_CONFLICT`, left the receipt prepared, and rolled back publication and selection. This was measured through the actual ports using the identical SQLite source tree from the pinned framework and public main baseline.

Recommend requiring the prepared digest to match inside the atomic publication/selection/receipt transaction. The control owner should explicitly approve the alignment and qualify the command service's prepared-intent binding, safe replay of an already-applied exact digest, and rollback on a conflicting digest. The candidate leaves control-plane implementation and D5 disposition open. [Raw D5 results](vhost-003-candidate/evidence/matched.json)
