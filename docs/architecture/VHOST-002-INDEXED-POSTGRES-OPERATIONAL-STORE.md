# VHOST-002 — Indexed PostgreSQL operational store specification

22 November 2026 · Architecture candidate for Radzi’s review · VHOST-003 requires owner approval

## 1. Problem and solution

A Quellight reply observer reads durable milestones and turn status. The separate turn worker checks for Stop. Each call through the pinned PostgreSQL store fetches one namespace JSONB snapshot under a row lock, hydrates all operational collections and selects the requested record. A write rewrites that snapshot. The transfer, decoding and lock domain therefore grow with unrelated history.

Replace the snapshot hot paths with typed operational records, exact identity keys, and SQL transactions scoped to the affected record, aggregate or lease. Keep one PostgreSQL store entry point and the current VICT runtime, control, and coordination ports. Keep hosted as an optional Fetch request boundary. A migration tool reads the legacy state in an operator-owned transaction. Serving code uses indexed rows exclusively after the version switch.

Quellight owns its HTTP routes, owner session, product table bindings and Vercel work and wake lifecycle. Mastra owns its memory data and capability bridge. VICT owns actor checks, governed effects, release and run identity, approval, ordering and durable outcomes. The database adapter realizes those contracts. General message fan-out, transcript chunks, market ticks, app business tables and provider calls remain outside operational storage. A simple site with no durable VICT work can run without either package. The reference for these boundaries is GOV-007 and §§12–14. [VICT System Reference at main baseline](https://github.com/radz2291/vict-02/blob/6b420a3e9eada6f694cc2550debda7753316b5b3/docs/VICT-SYSTEM-REFERENCE.md)

### Acceptance scenarios

- An application reads one actor, turn, Stop flag or stream cursor page while other histories grow. Storage transfers only requested fields and records.
- Two clients race the same run revision, approval, scope or command identity. Exactly one applicable transition wins, duplicate requests observe the recorded result, and a conflicting digest fails closed.
- An operator recovers after lost response or process death. Durable intent and receipts preserve uncertainty and identify the correct continuation, without automatic external replay.
- An application using pinned C12 memory or trusted SQL keeps the same-client lease checks. Stale owners cannot mutate after expiry, deletion or a migration epoch change.
- An operator can verify the source, replay a synthetic rehearsal, account for every snapshot collection, and demonstrate one write authority through cutover and rollback.

### Terms

| Term | Meaning |
| --- | --- |
| Namespace | Existing server-selected VICT persistence boundary. Actor is a separate authorization identity. A database role with namespace access still relies on VICT actor checks. |
| Aggregate | Records that must change in one public port call, such as run state and its event sequence or stream counter and milestone. |
| Fence | Monotonic scope generation bound to actor, owner, purpose and DB-time lease expiry. Revision is a separate record-level compare-and-set value. |
| Writer epoch | Monotonic storage-authority generation for one namespace and one selected writer. Distinct from a scope fence, runtime activation and application release. |
| Effect receipt | Durable observed or unresolved result of an effect attempt. A host response or wake acknowledgement alone conveys no settlement. |
| Cursor | A position in one stream or run. Durable stream gaps can reflect transient events. Sequential and orchestration event sequences each retain their own ordering contract. |

## 3. Storage contract and DDL map

### Types and constraints

- Schema version 2, descriptor format 1. Separate operator-owned schema metadata and namespace writer descriptor. Runtime migrate false verifies version, declared indexes/constraints via a migration manifest, and admitted namespace/epoch. No runtime schema creation. The operator provisions namespaces and scope/effect quotas. Consider explicit compatibility handling for callers that formerly relied on auto-creating a namespace via migrate false.
- Use committed versioned migrations and explicit ownership. One restricted runtime role per isolation domain, distinct migration/backup role. Qualify TLS including hostname and both pooler hops where applicable, unnamed parameterized queries, transaction-local timeouts, and connection caps. Fixed server config selects schema/namespace. Private schema grants and RLS where configured protect the storage boundary. A trusted SQL client with broader grants is part of the privileged app deployment and is never request-derived.
- All keys and indexes below begin with namespace, except schema metadata. Names below are target names. Give parent and dependent rows composite same-namespace FKs when the source already guarantees the relationship. Preserve valid legacy workflows with optional or cross-port references through validation and a reconciliation report. Do not add new mandatory FKs for optional actor, activation, application release, or correlation links. No cascades across governance, effects, audit, memory, product, or other ports.
- Bind namespace and coordination keys as source-compatible text where legacy SQL already enforces representability. For JS-ordered and composite operational keys use distinct columns and big-endian UTF-16 code units encoded as bytea. This preserves bytewise equality and code-unit lexical order, including NUL and surrogate cases. Match actual source identifier validation. For a valid encoded identity whose composite B-tree key could exceed supported tuple size, use a namespace/digest bucket with transaction-serialized allocation and exact raw-key comparison to a surrogate. Explicit sorting for compatibility lists with such keys uses the JS comparator after bounded SQL paging. Bounds for common indexed hot keys are a Gate A fixture. Do not silently truncate or treat digest equality as identity.
- Store a record’s opaque data as a restricted, versioned **tagged JSON encoding as bytes** with the source private codec's ordering and supported value semantics. Project typed SQL columns for keys, state, guards, metadata and ranges. Marshal boundary values with the existing port validation, exact comparison and detached-return behavior; preserve insertion order, explicit undefined, binary tagged values where allowed, number semantics and opaque stream/event strings. Do not use JSONB equality for JSON.stringify-based replay or decode NUL/lone-surrogate strings to PostgreSQL text. Bytes and indexed projections are committed together and checked by import/audit parity.
- Counters and epoch use bigint with nonnegative CHECK and a Number.MAX_SAFE_INTEGER guard wherever exposed as a JS number. Use bigint epoch milliseconds for VICT-record timestamps if their contracts use safe integers, timestamptz for DB-clock lease fields already stored as such, and exact safe conversion. Use CHECK for closed enums and nullable state-dependent fields, plus validated transition predicates. Preserve insertion ordinals only where observable. Allocate them from a private monotonic sequence with serialization when commit/insertion order is contractual, instead of inferring order from timestamp or DB scan. A gap in a private ordinal has no public meaning. Per-run event sequence and per-stream clock are separate dense counters with port-specific starts and durable-gap rules.
- No automatic deletion to satisfy limits. Statement and response budgets, role connection limits, per-aggregate keyset pages and configured retention protect serving. The defaults of 1–10 connections, legacy maxSnapshotBytes/maxStateNodes, and scopes/effects caps remain documented. In v2 the snapshot limits apply to legacy import/export verification and stay accepted options. Admit per-record and per-aggregate minimum compatible limits only after measuring existing values and defining failure semantics. Keep existing no-limit calls semantically complete, fetching bounded SQL pages within one consistent snapshot. They may return large logical results and need explicit capacity acceptance. Current consumers needing unbounded active stream replay get a measured envelope, with bounded page adoption as separately approved app work if needed.

Illustrative target DDL for the independently advancing stream clock and durable event table follows. The table map above is normative for the proposed design, with column types refined against the exact port declarations during implementation.

~~~sql
CREATE TABLE ops.stream_clock (
  namespace text NOT NULL REFERENCES ops.namespace_state(namespace),
  stream_id bytea NOT NULL,
  last_seq bigint NOT NULL CHECK (last_seq BETWEEN 1 AND 9007199254740991),
  PRIMARY KEY (namespace, stream_id)
);
CREATE TABLE ops.stream_event (
  namespace text NOT NULL,
  stream_id bytea NOT NULL,
  seq bigint NOT NULL CHECK (seq BETWEEN 1 AND 9007199254740991),
  kind text NOT NULL CHECK (kind <> 'text.delta'),
  created_at_ms bigint NOT NULL,
  payload bytea NOT NULL,
  PRIMARY KEY (namespace, stream_id, seq),
  FOREIGN KEY (namespace, stream_id) REFERENCES ops.stream_clock(namespace, stream_id)
);
-- Exact projection and keyset predicate for a page.
SELECT seq, kind, created_at_ms, payload
FROM ops.stream_event
WHERE namespace = $1 AND stream_id = $2 AND seq > $3
ORDER BY seq LIMIT $4;
~~~

### Why full indexed storage

| Option | Result and operational cost |
| --- | --- |
| Raise snapshot cap, tune pooling, co-locate | Lowest compatibility cost. Retains namespace transfer, lock amplification, shared capacity ceiling and ambiguous project billing impact. Useful as baseline or measured bridge only. |
| Transactional read projections | Could remove hot Stop and status bytes early. Must version projections atomically with writes and validate parity, including cursor clocks and effect truth. Keeps old full-write cost and the legacy writer's one-row lock. Any projection that still invokes the existing fenced path pays for its full snapshot SELECT even if the point value is indexed. Reversibility has value if the legacy pressure becomes urgent. |
| Indexed operational store | Recommended endpoint. Point lookups and cursor scans scale with the relevant key and page. Writes lock their aggregate. Requires versioned import, exact compatibility tests, explicit connection/retention policy and an owner-approved cutover. |
| Provider SDK, broad hosted replacement or domain database unification | Adds coupling beyond this project and blurs authority. A future capability-specific spec can evaluate it with new evidence. |


## 4. Transactions and per-port behavior

### Common execution rules

1. Capture, clone and validate the call before any asynchronous queue point. Bind a server-selected namespace, each input’s existing VICT identity, and an instance epoch. Reconstruct detached results with the exact existing shape and error vocabulary. Drive exact-match replay from stored receipt identity and digest. Return the original observed value where the port does so, including behavior when the live head has since advanced.
2. Use one client per transaction from BEGIN to COMMIT/ROLLBACK. Simple unleased point reads use one indexed MVCC statement with version and namespace guard. Multi-query aggregates use a stable snapshot or one composed statement. Leased reads and writes validate scope and epoch in the transaction, before and after trusted work when applicable. Supports check-only operations without a namespace snapshot read or exclusive namespace-row lock.
3. Write admission takes a shared lock on the bound epoch descriptor, compatible with other writers, before any mutable aggregate locks. Migration takes an exclusive epoch lock, waits for admitted transactions, revokes the old write path and advances the epoch atomically. Normal transactions never update that descriptor. Per-scope lock precedes owned aggregate or product/memory rows. Lock heads that exist independently of the selected record for absent-row CAS. Take deterministically sorted aggregate locks for cross-run batches. Recheck predicates after lock acquisition. Enforce atomicity with SQL constraints plus conditional transitions. Use transaction-local internal operations for composites and keep external I/O out of transactions.
4. Preserve the public trusted-SQL callback and same-client assertInTransaction. At first release, serialize **public arbitrary SQL callbacks** with an independent callback-admission lock per namespace before taking the first scope lock. The internal operational single-scope path needs no callback lock. This conservative path preserves C12 thread→resource validation and permits guarded point paths to proceed in unrelated scopes. In the existing callback, revalidate both leases before commit. Assert on the actual transaction client, with no pool checkout or nested public store call. Qualify a complete lock-order trace for every C12 and Quellight callback. A nested callable port requiring a second scope must join a known same-client path or be refused before waiting. Unfenced read-only pool SQL retains its trusted scope and restricted DB grants. Any current consumer depending on a broader raw-client pattern is a compatibility issue for Gate A.
5. The hosted lease clock uses PostgreSQL clock_timestamp semantics as the current store does, including expiry recheck after a callback. Timer, attempt, command and confirmation ports preserve their separate explicit input-time semantics and exact equality boundaries. No worker clock becomes a substitute for the hosted lease clock. Connection, lock and statement timeouts produce safe errors. A lost COMMIT acknowledgement leaves the outcome unconfirmed. Consult durable receipts and guard state before retries. Limit any internal deadlock/serialization retries to a proven pre-commit abort and to an SQL-only replayable operation.
6. Internal read pages use an index/keyset and stable ordering. Every existing result and optional/omitted limit remains compatible. There is no fallback that fetches a whole namespace or rehydrates unrelated stores. Tests compare observed ordering before assuming commutative operations or a PostgreSQL collation. Any concurrency behavior relying on global serialization must have an explicit replacement guard or documented compatibility decision.

### Rollback and restore contract

- **Before any candidate commit with write authority.** Close candidate admission, drain sessions, verify the candidate contributed zero authoritative changes including product or memory effects and epoch-controlled jobs. Verify old backup, receipts, held scopes and disabled scheduler. Activate a new monotonic rollback epoch and exactly one approved legacy writer after revalidating generations and privilege revocation for the candidate. The frozen source and shared coordination floors remain authoritative.
- **After a candidate commit.** Freeze both admissions, capture all three storage domains at a consistent recovery boundary, reconcile in-flight and uncertain effects using external evidence and exact keys, and preserve the indexed history. Prefer recovery on the indexed format from a verified compatible build or authorized roll-forward using timed backup/PITR and restored state verification. Restoring the old release alone would drop newer changes and could duplicate effects. Legacy reactivation requires an explicitly approved and rehearsed checked reverse translation of **all** post-cutover authoritative state, plus exact legacy size and node admission. If that is infeasible, remain quiesced and recover on indexed storage.
- **Backup/restore acceptance.** Time an actual isolated full and recovery-point restore of operational and external product/memory DB domains. Restore epoch, fence floors and tombstones, verify counts/hash/authority and compare last committed and externally observed effects before enabling one writer. Recover committed records via source WAL or captured durable change data when available. A physical restore that precedes an externally applied effect requires reconciliation, even when pure SQL data matches the restore point. No automatic replay of unresolved external effects, and no claim of cross-service atomic backup.
- **Retention.** Preserve default historical results, evidence and stream sequence clocks. Never delete active runs, required checkpoints, open approvals, unsettled receipts, live leases, active idempotency windows or tombstones by age. Archive eligible terminal, immutable data with manifest and tested restore. Ensure authorized deletion removes its intended private payload without weakening tombstone or minimum audit/receipt evidence. Retention duration, storage tier and legal/product dependencies are owner decisions. Scale bounds shape required usage and mode eligibility before archiving changes any observable port behavior.
