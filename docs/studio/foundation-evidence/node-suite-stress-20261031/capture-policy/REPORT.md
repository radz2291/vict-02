# Capture policy candidate

Owner-authorized isolated branch `codex/capture-policy-20261031` starts at exact source `41c7b4129ee0c72a80cb7ec29f4a10c4489eef07`. Root source/build, provider configuration, browser state and actual owner apps were not mutated. Dependencies were read from existing installed dependencies; ignored compiled dependencies were copied only into this isolated checkout. No activation, provider call, publication or push occurred.

The shared capture package no longer defaults to 512 KiB JPEG, 1600×1200 pixels, 2,000 DOM nodes, 6 MiB data/SVG, 4 MiB resources or 8/5-second task deadlines. It inspects the complete DOM and captures the actual visible viewport intersection. Cropping remains explicitly measured and reported. JPEG uses one quality choice, without lowering quality to fit a quota. Real canvas dimensions and JPEG output type are checked. Explicit consumer-selected width/height/byte policies remain optional; `RENDER_CAPTURE_LIMITS` is deprecated historical metadata and is never an implicit policy.

Optional `AbortSignal` is additive to the public capture API. Source fonts, library import, rasterization, decoding and encoding waits stop on cancellation, and owned blob fetches receive the signal. Cancellation does not pretend underlying unabortable library work was killed: the shared scroll engine remains quarantined until its actual promise settles, or the host reloads. The existing pinned rasterizers remain unchanged. The dependency has its own font-readiness behavior; the shared path awaits font readiness before starting it. Unsupported paint/resources or dependency warnings still refuse truthfully.

Studio removes its duplicate geometry/byte/metadata/target/style limits, pending broker and inference deadlines, forced 16,384 output tokens, and editorial assessment count/text limits. The run signal reaches shared capture through a small AgentChat/Designer pass-through; manual recovery capture also aborts on Stop/destruction. Assessments retain their full public response. Strict assessment fields/types and `notEstablished` remain; every model interpretation still has `semanticClaimsVerified:false` and does not establish interactions or source completion.

The default upload wire is standard multipart with exactly one `metadata` JSON field and one JPEG `image` field. This avoids shifting the former metadata quota to HTTP's header ceiling. Legacy JPEG plus `x-vict-capture` remains accepted for read compatibility. No authentication, CSRF, origin or ownership bypass was introduced. The existing launch script already sets the adapter body limit to Infinity; explicit deployment/platform policies remain external constraints.

`capturedAt` remains validated timestamp provenance, not an elapsed task deadline or independent freshness proof. No arbitrary age/future-skew cutoff or new clock-synchronization requirement is imposed. The actual fences remain: authenticated owner, unpredictable single-use capture ID, exact document/revision/digest/epoch, browser source/runtime/DOM/control/scroll/geometry checks, and same preview metadata plus identical image bytes before and after inference. A timestamp lower bound alone would not prove current pixels and can reject valid captures across clocks.

JPEG signature/frame-dimension admission is shared through public `@victframework/ui-ai-svelte/capture`, with no DOM access at module import. Studio reuses that helper. Positive dimensions must match the JPEG header; this does not claim complete entropy decoding. Existing same-origin blob-only, credential omission, redirect refusal, static PNG/JPEG/APNG checks, SVG references, fonts, owner clipping, portal, live-media and unsupported-geometry protections remain. Real browser canvas/codec capacity, resource availability, machine memory, provider schema/context support and pinned dependency behavior remain limitations, not universal unlimited-resource promises.
