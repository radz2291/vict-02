## Shared boundary and thin host changes

- Public runtime `awaitAgentDelivery` releases only transport ownership on abort. Pending promises remain observed, including late rejection. It cannot claim successful delivery after abort.
- Adapter passes the existing abort signal into public event sinks and uses the shared cancellation-aware wait. Cancellation in the stream/early event path is classified as cancelled; the thread hold releases before a blocked handler is released. No new normal source/tool delivery is started after abort; an already issued callback stays observed but cannot resume the cancelled producer. A cancelled terminal event remains separately recorded.
- Public hub subscribers may supply an AbortSignal. Owner abort or unsubscribe detaches the subscriber and wakes its blocked delivery. Durable ledger append remains awaited; the generic helper never races that ledger write. Existing sync false/pull semantics remain.
- Turn-executor still drains its serialized publication chain before durable turn settlement. Publication failure is reported as VICT_TURN_STREAM_PERSISTENCE_FAILED even if cancellation was requested; it is not hidden behind cancelled status. Protected effects remain uninvoked in that negative case.
- Studio exposes its existing run signal to the HTTP host, uses the same shared delivery boundary for initial and later emits, and avoids starting setup after early cancellation. Run abort errors the native TransformStream controller and aborts its writer. A pending write can therefore release without client reader closure; writer.abort alone did not provide that guarantee.
- Root's approved main-server changes are preserved in this commit: no global four-run cap, no eight-output/twenty-operation instruction ceiling, and full coverage/tool-failure projections. One active turn per source-owner session remains BUSY; different authenticated owners are independent.
- Synchronous parser diagnostics are deferred until an awaited boundary while preserving every actual safe evaluation. Tests now allow one pre-invocation validation pass and assert current VICT_TOOL_INPUT_INVALID rather than inventing duplicate parser calls or expecting the invocation-body STUDIO_AGENT_READ_QUERY code.
- Adapter revision6 covers cancellation-aware delivery and the separately owned passive-presentation amendment. Old adapter-bound activations still require explicit rebinding; source schemas, authorization, stale/draft checks, acknowledgements and provider identities are unchanged.
