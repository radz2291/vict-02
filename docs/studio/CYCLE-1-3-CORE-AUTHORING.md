## Architecture candidate

### One component contract, package-owned knowledge

Reuse `UiExtensionDescriptor` in `@victframework/ui` and the existing Svelte Component ABI. A neutral authoring companion references the exact descriptor; it adds discovery and semantic guidance, never a second props/events/slots model. Renderer packages own their descriptor, implementation and companion registration together. `ui` owns pure registration validation, deterministic knowledge digest/index/bounded selection helpers and shared declarative semantic rules. `ui-svelte` owns general catalog registrations; `ui-ai-svelte` and `ui-flow-svelte` own eligible specialist adapters and registrations. `ui-editor` owns reusable composition/transaction helpers. Studio composes explicitly installed registrations and supplies discovery/edit tools.

Descriptor-derived information: IDs/revisions, props/defaults/types, slots, outputs/payloads, ABI and renderer identity, style targets and inspection limits. Authored-once semantic information: purpose/category, correct composition/required dependencies and placement, sibling identity scope, paired-part keys, label ownership, controlled prop/output pairs, host requirements, examples and explicit exclusions. Do not infer these rules from TypeScript or guess them from export names.

The registration path is package descriptor + implementation + authoring companion → validated installed registry → renderer/editor catalogs and knowledge index → bounded agent discovery/selected contracts → canonical commands → compiler and renderer validation → browser acknowledgement. Recipes use that path as convenient prepared compositions; supported registered components are also insertable without requiring a recipe per component.

Registration/version identity is separate from document identity: knowledge digests cover exact descriptor plus guidance/dependencies/eligibility. Compact family/category/query discovery returns stable IDs, revisions and digests; bounded selected-contract reads take requested IDs and known digests and return unchanged markers or changed contracts with provenance. Do not cache source facts under knowledge digests. Dependency closure is bounded and explicit; missing/revision-incompatible dependencies fail registration. Existing descriptor IDs/revisions and saved documents remain unchanged. New adapters receive new IDs and explicit revisions. Do not silently migrate existing documents or reinterpret immutable component revisions.

Internal helpers, unsupported upstream patterns and host-only APIs have explicit dispositions; installed exports do not automatically become authorable. Tests must detect missing/duplicate registrations, descriptor drift, unsupported claims, invalid examples/placements and renderer mismatch. Maintenance demonstration adds an eligible registration and changes its contract in a controlled fixture, proving derived discovery/schema/digests update without parallel prompt/catalog edits.

### Supported authoring and specialist adapters

Audit canonical support, renderer/editor support, manual tools, agent tools and verification separately. Close existing date/time/list-state, native text-reference, heading and styling gaps through current commands and exact validation. Expose a bounded generic insertion/composition path for elements/text and registered components whose full canonical path exists, retaining explicit slots and exact typed bindings; recipes are accelerators.

AI/chat authoring adapters should cover real supported presentation compositions and typed composer/message behavior using the existing ABI, public specialist components and slots. Proposed eligible starting set: conversation (messages/composer slots), message (role/text, only declared intent outputs where implemented), prompt input (value/busy, typed valueChange/send and stop). They do not attach Studio's provider backend to authored chats.

Proposed Flow path for independent challenge: canvas with node/edge declaration components in slots; declarations carry scalar id/label/x/y/source/target and register through a package-local rendering context, which maps to public Svelte Flow arrays. Persisted truth remains those canonical component nodes, with no second stored graph or JSON-string object escape hatch. Challenge slot mounting, occurrence provenance, repeated instances, controlled updates, cleanup and Design/Interact differences before implementation. Positions authored in these new user components are their explicit presentation props, distinct from Studio Structure's ephemeral layout. Arbitrary callbacks, custom executable nodeTypes, rich object-array graph state and workflow execution remain excluded unless a full canonical path exists. Required behavior that cannot fit existing canonical types is an amendment question with an exact gap. Advertise only implemented and independently demonstrated adapters.

Existing unpinned component resolution and application identity are not changed by discovery digests. New authored component nodes pin descriptor revisions. Meaning/default changes require a new descriptor revision with old support retained; guidance-only changes update knowledge digest without pretending saved source changed. Renderer identity remains the existing explicit identity boundary, not an invented automatic code digest.

### AC-01: registration data, projections and compatibility

Use a pure companion schema `vict.ui-authoring@1`, alongside—not inside—the existing serialized document. Its package record carries `packageName`, installed `packageVersion`, companion schema and explicit export dispositions. Each registration references its existing descriptor and exact implementation in the renderer-owned install unit; the neutral companion contains no Svelte implementation/function. Derive descriptor facts from that reference and renderer capability facts (`required`, `requiresParentContext`, `compositionSlots`, forwarded style targets) from the actual implementation. A neutral projection of those implementation capabilities is equality-checked at assembly, never manually treated as a competing capability declaration.

Registration companion fields: stable label/family/category/purpose, eligibility (`standalone`, `part`, `host-required`, `excluded` plus reason/prerequisites), exact dependencies `{id, revision}`, semantic rules described below, serializable canonical example/seed fragments and package provenance. Example fragments contain existing `UiNode`/local-state data; reusable helpers remap their node IDs and state references. They do not contain executable recipe callbacks. `ui-svelte` must not depend on `ui-editor` to own this data.

The package install unit projects descriptors/implementations in their **existing order**; the discovery index may be sorted separately. Existing unpinned selection stays last-registration-wins. A shared effective-descriptor resolver uses exact node revision when present, otherwise the same last match as the compiler, including newly affected editor slot/property reads. New inserted components pin exact descriptor revision. Never append a new revision to an existing ID and silently change old unpinned behavior; use a new ID when old unpinned behavior cannot otherwise be preserved, or return the exact migration/contract decision. No automatic source migration.

Retain an independently checked compatibility baseline keyed by `(id, revision)` for existing descriptor bytes and relevant renderer capabilities. It is distinct from the live knowledge digest. Same-revision interface/default/meaning drift fails against those pins; intended incompatible changes need explicit new identity/revision and old support retained. A test-fixture new revision demonstrates invalidation without changing the live legacy current selection. New eligible registration requires one package-local entry and its implementation/descriptor; generation/checks derive contracts and discovery without prompt copies. Snapshot pin maintenance is explicit release/compatibility evidence, not another manually maintained schema.

Knowledge digest covers exact descriptor, companion schema/data, package provenance, relevant derived implementation capability data and exact dependency digests. Package version, descriptor revision, renderer implementation identity, companion version and digest are distinct. It does not hash arbitrary renderer code or alter applicationVersion semantics. Registry creation rejects duplicate exact registrations, missing/incompatible dependencies and cycles. Bundle closure has an explicit item/byte/depth budget; if a requested closure cannot fit, return a structured incomplete/refusal result with pending IDs/cursor and the budget cause. Never label a partial closure complete. Unchanged digests omit contract bodies; changed dependencies invalidate their dependents. Source cursors and captures always use independent current-source freshness.

### AC-02: one shared semantic admission policy

Neutral data rules cover: `ancestorSlot` (allowed provider IDs/revisions and slot), `requiredParts` (required compatible child family/slot), `uniqueValue` (component prop unique within a named nearest-provider scope), `pairedValues` (matching keys in specified paired part families/slots), `labelOwnership` (component owns its label or explicitly associates an external target), `controlledPair` (prop/output with matching declared type) and `hostRequirement` (required non-executable host capability/state prerequisite). Descriptor props/slots/outputs and implementation-required slots remain derived facts. Placement/identity/pairing violations are source-linked errors when provable. Label duplication and deliberately uncontrolled controls are guidance/warnings unless the contract explicitly requires otherwise; do not turn every unbound control into a defect.

`ui` owns pure semantic evaluation and structured diagnostics; `ui-editor` supplies canonical insertion/move helpers and invokes these rules. Reuse the existing occurrence/context traversal, including wrappers, local-definition slot substitution, repeats and conditionals. Studio invokes the same rules for manual/recipe/generic agent edits, move and Source admission, plus Save/Run preflight. Validate complete transactions, allowing paired parts to be assembled in one atomic batch. Recipe eligibility cannot bypass generic admission.

Compatibility treatment is explicit: historical descriptors and old documents retain canonical validity. New authoring rejects newly introduced provable semantic errors. Unchanged legacy violations are carried as bounded warnings, so opening, replaying or saving an old source does not silently reinterpret it; changing the offending identity/context must repair it. Source replacement compares before/after semantic violations just as other edits do. New specialist IDs require the strict new rules. Save/Run use the same accepted-source policy and surface remaining compatibility warnings. Tests must prove new-invalid refusal and legacy reopen/history, rather than making a blanket claim that older sources are newly invalid.

Static certainty is limited: literal duplicate values and definite pair mismatch can fail; dynamic refs, repeats and conditionally present parts produce an explicit unresolved diagnostic rather than a proof of uniqueness. For identity-sensitive renderer contexts, validate evaluated IDs/keys at the owner context and refuse ambiguous presentation with bounded source-linked feedback; do not choose the first match. Generic inserts carry exact component ID/revision, typed props and declared slot names through existing canonical commands. Missing mandatory composition fails clearly at final admission. Native insertion reads the active semantic element catalog and native/text command contracts, not fabricated component descriptors.

### AC-03: initial Flow composition contract

Proposed new descriptors: `vict.flow.canvas@1`, `vict.flow.node@1`, `vict.flow.edge@1`. Canvas props are scalar label/height and boolean controls/minimap/background choices; its `nodes` and `edges` slots contain context-owned declarations. Node props are `id`, `label` strings and finite `x`, `y` numbers; edge props are `id`, `source`, `target`, optional label strings. All have an actual forwarded `root` style target. Node/edge declare canvas-slot host requirements and are not standalone composition previews. Missing context shows a truthful source-linked unavailable diagnostic. No drag/connect/delete or execution output is advertised. Canvas viewport/selection may be ephemeral; its declared presentation outputs, if any, must remain typed and emit-only.

Canvas owns a per-instance rendering context. Declaration snippets mount inside that provider even when their implementation has no visible declaration element. Every entry stores its exact runtime `occurrenceKey`, canonical nodeId and **child** `presentation.target('root')` attributes. Code-owned custom visible node and edge renderers forward those child attributes onto real targets. Canvas forwards only its own target. Source selection never reconstructs an occurrence from graph ID, label, DOM position or array index. A hidden registration element is not a selectable substitute for the visible graph card/edge.

Graph IDs are local presentation keys, distinct from source IDs, scoped to one canvas occurrence. Validate evaluated uniqueness per canvas, edge IDs and node IDs in their respective namespaces, and unambiguous edge endpoints. Two canvases/repeated definitions have isolated registries; repeated evaluated duplicate IDs fail visibly, not silently overwrite. Register/update/unregister use unique ownership tokens, scoped by exact occurrence and plan generation; cleanup only removes the entry it owns, so old cleanup cannot remove a replacement. Batch a mount cycle before final endpoint checks to avoid transient dangling-edge reports while siblings register. Conditional removal, repeat replacement, remount, prop update and Undo/Redo rebuild disposable arrays from canonical declarations; no second persisted graph.

Initial Flow is **read-only authored topology/positions** with pan/zoom/keyboard selection. Disable upstream node dragging, connection creation, deletion and independent array mutation. In Design visible graph targets select exact canonical children; Interact only changes ephemeral viewport/selection. Position changes use normal authoring props/history, not hidden graph drag writes. Custom executable nodeTypes, arbitrary objects/callbacks and workflow execution remain excluded. A narrow actual-render proof must establish visible child occurrence mapping, two canvases and lifecycle before expanding the adapters; if the ABI cannot do so, stop with the exact gap.
