## PV-05 — reusable style-source authoring

The later independent challenge identified that per-node conditional style operations did not expose reusable `UiStyleSource` definition and reuse. The new public `ui-editor` helpers `defineStyleSource`, `attachStyleSource`, `detachStyleSource` and `removeStyleSource` construct ordinary canonical `replaceDocument` transaction drafts. They retain source identity, compiler validation, history and explicit persistence. No neutral schema or renderer semantics change.

Definition creates a fresh identity by default; shared replacement requires explicit `replace:true` and an existing source. Attachments preserve authored order, default to append, and support a bounded valid insertion index. Existing local styles remain unchanged and keep their canonical precedence. Detaching preserves the source; deletion refuses references from every authored node, including detached nodes/templates, and component-definition `baseStyle` references. Element/component attachment surfaces are accepted; component target capability checks remain in canonical compilation.

Structural helper refusals use exported `StyleSourceEditError` with code `UI_STYLE_SOURCE_EDIT`, a bounded field (`sourceId`, `nodeId`, `index` or `replace`) and optional bounded source/node identity. Canonical diagnostics are preserved separately. Typed declarations retain existing text/token/binding values, condition and pseudo fields. No opaque JSON or arbitrary script operation is introduced.

Focused new helper tests **6/6 PASS**; combined registered-authoring regression group **11/11 PASS**; `ui-editor` package TypeScript build PASS. Tests demonstrate reuse on two elements and a local component, explicit shared updates, preserved local overrides, ordering, reference guards, Undo/Redo, Save/reopen and compiled condition/pseudo/token/binding retention. Initial test failure expected the nested unknown-token diagnostic at the top level; the assertion was repaired to retain the authoritative `UI_EDIT_VALIDATION_FAILED` wrapper and its `token.missing` diagnostic. Product behavior was unchanged by that test repair. Agent-schema integration, installed-consumer refresh and independent verdict belong to the next stage-manager candidate.
