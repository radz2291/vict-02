## What is exposed today

Structure projects a single authored UI document: element, text, component instance, repeat, conditional, slot and portal source nodes; declared local state; local/library component definitions; direct expression references; invoked action IDs and navigation route IDs. It shows source relationships, not execution order, live values, expanded runtime records, action implementations or a complete application/page topology. Component internals are not recursively exposed from the installed component library. This boundary is reasonable, but the interface needs to explain it.

The card system is coherent: quiet white cards, a stable selected border, semantic UI labels, category icons, named sockets, counts, edge colours and several line patterns. Read/write/action/definition/navigation relationships have labels, so meaning does not depend on colour alone. Source IDs and declared edge locations are retained. Read-only sockets cannot create bindings. Canonical source and authored styling were not changed by this review. The previous stable-zoom evidence remains valid within its recorded 30-node horizontal/vertical cycles.

## Findings and proposed resolutions

| ID / priority | Observation and consequence | Proposed resolution — not implemented |
|---|---|---|
| NV-01 / high | Selected connections bypasses the hierarchy filter. Collapse, State and actions, Definitions and templates, and Show text nodes remain enabled but do not change that graph. CUA: default 14 nodes/21 edges remained identical after collapsing Screen and enabling all three switches. Switching to Whole hierarchy respected the collapsed root: one node/no edges; expanding all with the options on gave 40 nodes/47 edges. | Give visibility controls one consistent effect in both views, or explicitly disable and explain controls that do not apply. Show visible/total counts and why content is hidden. |
| NV-02 / high | Graph selection and connection scope can diverge. CUA: selecting the heading updated Selection to Heading/Create your workspace, while the graph retained the root's 14-node network. View → Frame selection then changed it to one heading/no edges. The low-zoom Frame selection button only changes the camera, whereas the menu command calls `reveal`, changing focus and sometimes visibility flags. | Separate camera framing from changing scope. Label the current scope with its item name; make scope changes explicit and predictable. Preserve ordinary click inspection without an unexplained graph jump. This qualifies the earlier broad “Frame selection only moves the camera” wording: the prior browser evidence tested the low-zoom button, not the menu command. |
| NV-03 / high | Whole hierarchy uses edit-safe `occurrence` eligibility to decide default source visibility. Valid repeat templates, conditional branch children, and local definition/slot fallback content are hidden when Definitions and templates is off. The compiling fixture hid `template`, `yes`, `no`, `definition`, `slot`, `fallback`; enabling the option revealed all. Hidden conditional content is not naturally understood as a definition. | Separate visibility from edit permission. Show logical source ownership and useful collapsed summaries for repeats/branches/slots; retain existing edit guards. Use explicit visibility categories rather than one misleading catch-all. |
| NV-04 / high | Named conditions and their dependencies are absent from the graph. A valid conditional driven by `state.visible` has branch containment but no condition/state connection, because only nodes are recursively scanned, not the conditions registry. Style sources, tokens and assets also have no graph representation/dependency expansion. | First expose conditional predicates and their controlling state in plain language. Offer style/theme/asset dependencies as optional detail, with a clear declaration of the graph's coverage. Avoid dumping every registry into the default view. |
| NV-05 / medium | Branch/slot/template meaning is retained in original edge labels but flattened in the visible socket and relationship grouping. `branch: show` becomes Children/Contains; the relationship UI does not render the stored path list. Repeat collection/key, conditional predicate, slot fallback ownership and portal target have little useful Overview treatment. | Preserve the quiet card format while adding concise semantic facts: “When …”, “Otherwise”, “Repeats …”, slot name, fallback, overlay target. Make exact paths available on demand. Keep parent/child hierarchy distinct from data flow. |
| NV-06 / medium | Search does not use the semantic labels displayed on cards. CUA: searching Heading returned zero items, while `onbTitle` found the heading and its context. The source probe reproduced this. Long labels are truncated to 76 characters before rendering; the card tooltip and Selection identity reuse the truncated value. ARIA identity can still say Container/Element while the visible type says Heading/Input. | Search displayed names/types as well as IDs. Retain full labels for tooltips and accessible names. Use one semantic presentation model for cards, Overview, search and accessibility. |
| NV-07 / medium | Selected connections expands through shared references to other users of that reference. A compiling 140-input fixture sharing one state key produces 141 visible nodes/140 edges when focused on one input. Above 120 nodes, ELK requests fall back to Dagre; Structure discards the returned reason. Generic group controls do not solve this in the connections view because collapse is bypassed. | Use a clearly bounded initial neighbourhood, with an explicit “other users” expansion/count. Surface the layout fallback when relevant. Preserve complete relationships in Selection without forcing them all onto the canvas. |
| NV-08 / medium | Socket counts are counts of visible edges; Selection uses the full source graph. A section can show “11 direct children” but “Children 5” in the filtered connection view. Parallel references to the same target/kind share sockets and can overlap; count 2 may mean two expression locations, not two different targets. In vertical layout, multiple kinds share a fixed 224px row and labels can ellipsize. | Qualify visible counts and distinguish target count from source-reference count. Offer related-item highlighting and location detail. Validate dense mixed-kind vertical/horizontal cases before accepting broad readability. No measured high-degree visual pass is claimed here. |
| NV-09 / lower | Compact text hiding removes sole literal paragraph/heading leaves, but similar label/option leaves remain as near-duplicate cards. State shows declared starting values, not live runtime values. Portal source ownership is projected although the compiler explicitly warns that native portal rendering is unsupported. | Apply a semantic, reversible text-compaction rule; distinguish source/initial values from runtime state; show capability warnings where relevant. Do not imply that a projected node proves renderer support. |

## Use-case assessment

| Use case | Current assessment |
|---|---|
| Small static page, ordinary containment | Useful; view mode, text compaction, search and hidden counts need clarification. |
| Form with input reads/writes and submit action | Best-covered case; direct declared relationships are readable at a suitable zoom. Counts/paths need clearer interpretation. |
| Conditional/responsive UI | Incomplete explanation: predicate/dependency missing, branch contents hidden by default, responsive conditions not expanded. |
| Lists/repeated data | Template source exists, but default visibility and collection/key explanation are weak. Runtime rows/records are intentionally not separate source nodes. |
| Reusable/local components and slots | Definitions/instance edges exist; slot names, fallback and instance-versus-template distinctions need stronger treatment. Installed library internals remain outside this projection. |
| Overlay/portal ownership | Logical children exist in projection; native portal rendering has compiler warnings. Actual runtime overlay behaviour is not established by this audit. |
| Many controls sharing state | Valid source can create an unexpectedly large connection neighbourhood. Large-graph visual/latency acceptance remains untested. |
| Multiple pages/navigation | Route reference IDs exist; this is not a page map, route implementation or cross-document application dependency view. |
| Low zoom, long names, keyboard/assistive use | Stable geometry is retained; low zoom still requires camera navigation. Long-name recovery and semantic accessible labels need work. A complete accessibility/contrast audit was not performed. |
