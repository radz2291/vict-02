The reusable `captureRenderedElement` utility in `@victframework/ui-ai-svelte` rasterizes the existing styled preview DOM through `html-to-image@1.11.13`. Studio identifies the displayed Design/Interact frame and clips it to its current canvas viewport. It does not construct an image from a source-document summary. Source dimensions remain fixed during rasterization, avoiding a capture-induced responsive reflow. The SVG viewBox handles the outer canvas scroll position. Nested scrollers with a nonzero offset explicitly refuse capture because this rasterizer does not preserve their scroll positions. Portalled UI outside the frame is outside capture scope. This is DOM rasterization with browser CSS support, not a desktop/OS screenshot; cross-origin fonts/images, external media, browser-native controls and unsupported CSS may limit fidelity. Such limitations remain relevant to independent browser comparison.

Capture association includes document ID, working revision, digest, epoch, timestamp, source and image dimensions, crop origin, viewport scroll offsets and device pixel ratio, preview mode, selection/composition and a SHA-256 fingerprint of the preview state. The browser compares source/preview state before and after capture. The server rejects another session's request, expired/reused IDs, stale source cursors, old timestamps, mismatched JPEG dimensions and excess bytes. It rechecks the current source after image inference. Preview metadata represents the captured instant; a screenshot never establishes behavior after that instant.

`studio.screen.observe` is a VICT read capability. A capture request follows the current browser session and source cursor. The authenticated CSRF-protected image route receives at most 512 KiB JPEG separately from ordinary JSON reads and delivery snapshots. Maximum image dimensions are 1600×1200. Images live only during the pending observation/model call, are never saved to repository or conversation history, and pending captures expire after 25 seconds or cancellation. The image model call has a separate 120-second deadline. Stop fences both browser capture and provider work. Only concise appearance text, image digest, bounded provenance and explicit limitations return through the ordinary tool result.

The observer calls the same configured provider/model using the existing Studio router and bounded provider seam. The low-level SDK prompt contains a `file` part with `mediaType: image/jpeg` and the actual bytes; the provider adapter translates that to its image format. It does not send the image as prose/base64 in a text-only tool snapshot or silently substitute a model. Private reasoning deltas are discarded. A successful image call returns `evidence: observed-appearance`, `interactionVerified: false`, and the exact model. Source facts, appearance and interaction evidence remain distinct.

## Independent challenge: external preview portals and state changing during inference

The fresh verifier correctly identified two gaps in candidate `b67baf14ad6b0ef017adc7fdadc45747a6e874ad`: an open preview-owned CatalogPortal is mounted outside `.design-frame`, so the frame image could omit the visible popup; and runtime/internal overlay state could change while the image model was working without changing the source cursor. The earlier successful image-only marker test did not exercise either case. These are retained findings; the initial proof is not promoted into evidence for open overlays or inference-time state stability.

The bounded repair deliberately refuses unsupported open portals rather than returning an incomplete image. Studio derives per-instance owner IDs from the actual `DocumentHost` roots inside the frame and detects visible external nodes with those `data-ui-owner` values. Unrelated Chat/Inspector overlays are ignored even when they use the same document style class. A visible preview-owned external popup returns `STUDIO_CAPTURE_PORTAL_UNSUPPORTED` before image inference, with an actionable close-overlay message and no image/appearance observation. Closing it enables frame capture again. This does **not** implement inspection of an open portalled popup; that remaining image-scope limitation must be judged against the acceptance criteria by the independent verifier.

The capture fingerprint now also covers actual owned DOM control states, including internal/unbound expanded/checked/selected state, current native values, focus/hover state, leaf text and scroll positions. A document-body MutationObserver watches only changes belonging to the captured preview; it catches an owned portal opening and closing during capture even if the final source/DOM signature happens to match its initial state. Portal presence, source/runtime signature, frame/viewport geometry and scroll are checked before capture, after rasterization, and after fingerprint hashing. The observer is always disconnected.

After successful model inference, the server requests a second current capture through the same authenticated bounded binary channel. It compares the source cursor, preview fingerprint/metadata, viewport and image geometry against the inspected image. A changed runtime/viewport/overlay, or a refusal during revalidation, returns `STUDIO_CAPTURE_STALE` and withholds the old appearance observation. The second image is not sent to the provider: one observation still performs exactly one model call. Successful results include `revalidatedAt` and `validation: same-source-preview-and-viewport-after-inference`. They remain evidence of the stated frame region and captured/validated instants, never proof of bindings, actions, external Studio chrome or future state.

`tests/ui/designer-capture-portals.test.ts` exercises ownership isolation, hidden portals, portal appearance during asynchronous rasterization, open/close races, unbound native/internal-state fingerprint changes, and an actual mounted catalog Popover's CatalogPortal outside the frame, including close-and-recapture. This is a DOM simulation using deterministic rectangle geometry and a mocked rasterizer, explicitly not real-browser pixel proof. Expanded server tests verify portal refusal and runtime/viewport/portal changes across the two captures while asserting exactly one model call. Final browser and exact-candidate independent verification remain required.
