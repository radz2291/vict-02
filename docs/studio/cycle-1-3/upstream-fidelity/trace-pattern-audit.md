## Shared finding and comparison limits

The existing wrapper layer flattened ten different compositions into three generic shapes: `TraceSteps`, `Tool`, and a few short additions around them. `ChainOfThought`, `Plan` and `Task` were aliases of the same file. `PatternShowcase.svelte` reinforced that loss by rendering the same steps, including planned/pending work, for all three. `Subagent`, `TestResults`, `Terminal` and `StackTrace` then reused those generic shapes where upstream provides materially different hierarchy, grouping and status treatment.

The pinned Trace primitives already provide the important visual grammar: muted compact lines, trailing disclosure chevrons, a left content rule with consistent inset, running shimmer, destructive error color, pending opacity and truncated titles. CodeBlock already supplies wrapped monospace content and compact size. Their presence and styled dependency provenance do not establish fidelity of the compositions built from them. Most corrections can therefore use the existing primitives and icons, without replacing tokens or adding a parallel design system.

The official examples place these compositions within an AI SDK transcript, a narrow `max-w-sm` demo container and a Replay button. VICT's two-column gallery cards, wider consumer container, fixture labels, theme and absence of upstream mock transport are not themselves defects. A host adapter must supply public activity, typed status, duration and callbacks; it must not infer private reasoning, perform commands, invent file navigation, or grant approval authority. Safe Markdown is an explicit content-boundary adaptation. It must not turn code/log/stack text into executable or unsanitized markup.

## Secondary variants and evidence required after correction

Plan description, Queue descriptions, Reasoning duration, Subagent running/details, Terminal error, Test Results suites and Stack Trace grouped frames are representable with additive host data and existing dependency components. They should receive visible gallery fixtures or clearly named state controls. Tool approval needs the existing Confirmation pattern and an explicit callback; a fixture callback must say that it is simulated. Tool Sheet needs either the pinned dependency closure or an explicit host-panel adaptation, with the final disposition recorded rather than silently omitted.

The gallery must instantiate the actual exported separate ChainOfThought/Plan/Task components. Task's fixture must have observed steps only; Plan may show future/pending steps. Trace status updates, content arriving after an empty running row, a user overriding disclosure while work continues, failure detail opening, and output growth all need interaction evidence. Static screenshots alone cannot establish these behaviors.

After authorized repair, capture comparable expanded/collapsed/running/error states in the packed consumer at desktop and narrow widths. Compare structure, hierarchy, icons, truncation, bounded code content and action placement; record host-theme/container differences separately. Keep existing safe-content and host-authority tests. Root coordinates serialized checks, screenshots and exact-candidate independent verification; this audit performs no build, browser run or verdict promotion.

## Authorized source repair disposition

The initial findings above remain preserved. The parent subsequently authorized repairs to these ten wrappers, three new separate components and `patterns/index.ts`, with no vendor expansion. This section records implementation intent, not a passing check or visual verdict. Root owns gallery fixtures and coordinated validation.

- **Chain of Thought:** separate export; aggregate running-first then error matches the main example. The legacy pending status remains a muted Circle, never a completed checkmark. Nested typed `code`, `badges`, `links` and `open` extend the old Step contract locally. Code details default open, while result links/badges default closed; readers can override each row. Links use the existing safe URL boundary. A pending activity is only a compatibility representation; hosts should use Plan/Queue for future work.
- **Plan / Task:** separate exports retain old prop shapes. Plan keeps Route, planned rows and progress; Task filters pending future work, removes progress and uses iconless nested activity. Task aggregate error-first follows its pinned example. Explicit titles remain host data; adapters do not guess tool verbs from opaque titles.
- **Queue / Reasoning:** Queue counts and groups within a single Trace, omits empty groups and supports `completedOpen=false` for the descriptions variant. Reasoning primary is iconless and can use `markdown=false` for whitespace-preserved text; `duration` or `showIcon` supports the documented icon variant. Safe Markdown remains the compatible default content adaptation. Empty text has no disclosure. Running defaults and reader overrides are independent.
- **Subagent:** summary state/duration and metadata use the existing Trace/Badge primitives. Description, nested activity and result now share the disclosure. Model/tools are labels only; the optional result uses safe Markdown. Running and pending icons are truthful. The host explicitly owns aggregate state.
- **Tool:** plain lines precede output and represent denied state. Completed/error output uses a compact bounded code body without redundant Input/Output header bars. Optional `details=true` exposes the supplied legacy input in a labeled nested disclosure. `approval` composes the existing Confirmation with an explicit host decision callback; it does not change tool state itself. `onOpenOutput` offers a chevron affordance calling a host-owned presentation panel. **The literal Sheet example is not replicated**: no Sheet closure was added. This is a presentational adaptation, not a backend limitation and not a claim of Sheet parity.
- **Terminal:** independent trace avoids duplicate command/input blocks; optional exit code produces the error title. A first nonempty running output opens by default, errors open by default, and reader choices persist through output/status updates. Output is escaped data, never executed.
- **Test Results:** optional structured `testSuites` supplies real suites, case outcomes, counts and bounded failure details. Required suite/test IDs keep user disclosure state stable. Main-example errors open by default; `errorsOpen=false` reproduces the suites variant's initially closed case errors. Existing `suites: Step[]` is retained as an activity fallback without falsely treating pending as skipped or running as passed. Raw output is inside the summary disclosure. Fixture counts are presentation data only.
- **Stack Trace:** the main example actually uses Terminal for the summary; the earlier table's CircleX recommendation applies to the separate frames example. The repair defaults to Terminal and adds `summaryIcon="error"` for CircleX. The first line remains a full destructive error, parsed application frames come first, and `node_modules` / `node:` frames are folded separately. Unparsed nonempty lines remain visible. `onFrameSelect` provides real host navigation; absent that callback the rows are inert rather than fake anchor links.

The Plan description, Queue descriptions, Reasoning duration, Subagent running/details, Tool states/approval, Terminal error, Test Results suites and Stack Trace frames variants are representable by these additive props. They are not all literal tutorial reproductions: upstream mock chat transport, Replay controls, fixed sample text and demo containers remain outside the wrapper contract. Tool Sheet specifically remains the host-panel adaptation above. The original 21-family coverage claim must not be restated as coverage of every tutorial variant.

Disclosure state is initialized from host state until a reader changes it, then preserves that reader choice during live prop changes. This intent still requires actual mounted transition tests and browser evidence. Source repair alone does not establish appearance fidelity. No builds, tests, browser runs or commits were performed by this lane during the source repair; the coordinated root checks and independent candidate verdict remain outstanding.
