## Implemented boundaries

- `capture-evidence.ts` projects only enumerated capture phase/reason, source revision, mode/covering state, attachment/layout, before/current frame/viewport rectangles, scroll and changed-fence names. It does not accept DOM text, full source, private reasoning, arbitrary provider errors or credentials. Refusal JSON is bounded at4096 bytes; JPEG/snapshot bounds are unchanged.
- Public `capture.ts` retains existing behavior/limits but distinguishes disconnected, no-layout, zero-size and outside-viewport errors. Studio's browser capture retains source/state/DOM/geometry/scroll/fingerprint/portal fences and records where refusal happened. The authenticated capture route forwards allowlisted refusal evidence rather than dropping it.
- Observation retries only raster/metadata transient stale capture once, with the same current cursor and no edit replay or extra image-model request. Missing/covered/hidden preview, portal, source and other refusals give bounded explicit recovery instructions instead. Post-inference source/preview/viewport/image SHA256 revalidation is unchanged. Capture recovery is not runtime interaction testing.
- Server terminal receipts retain unresolved tool-specific code/phase/reason, underlying engine termination, current confirmed edit revision, source counts and whether a current bounded appearance observation succeeded. Successful edits remain distinct from failed observation. UI wording no longer calls every tool failure an edit failure or repeats its applied-edit boundary in the same final timeline summary.
- Governed call IDs now correlate proposal/browser commit/ack/server receipts. Public Conversation can display one attempt with ordered expandable lifecycle stages, retaining refused attempts in their chronological place. Concurrent calls settle only their own IDs; unassociated validation events do not settle unrelated starts. Existing legacy activity presentation remains supported.
- `agent-progress.ts` retains bounded measured call/result/refusal counters, calls after a tool refusal, elapsed/tool/acknowledgement timings, first confirmed edit and actual authoring/vision request counts across detail compaction. Raw numeric or SDK `{total,...}` token counts are aggregated only when present. Missing counts remain unavailable; model steps and monetary cost remain unavailable. Overlapping tool durations are not wall-clock time. Stop/interrupted transport retains explicitly partial browser measurements and does not invent server/provider metrics.
- Every acknowledged edit returns and traces intermediate source coverage, avoiding another tool call. Automatic receipts bound missing IDs to20 and retain the actual missing count/more flag; full missing IDs remain paged. This remains source presence, distinct from the user request, intent, interactions and visual completion. The root-owned coverage helper defines registered-family/native compatibility details.
- Server retains root's bounded prepared compiler refusal as `lastValidation`, in addition to schema refusals, for the next overview read. Prompt/tool descriptions use exact generic registered insertion, seven canonical state types, native references and supported style operations; recipes remain accelerators, all83 hardcoding is removed, and bounded family/catalog/selected-contract/dependency/digest discovery is described accurately. No new product/effect/runtime interaction-testing tool is implied.
- Server imports/reexports root-owned `agent-edit-presentation.ts`; the old competing server schema block was removed.
