# VICT media and graphics

Reusable registered presentation for images, native video/captions, explicitly enabled video providers, supplied/custom icons, inert editable vectors and owner-managed assets. Components are available to canonical documents through `mediaAuthoringPackage` and `mediaAuthoringImplementations`, not only coded hosts.

The host wraps its document in `AssetProvider namespace="application-id"`. Supply `store` for a server/packaged asset backend, or use its origin-local IndexedDB store. Each document/application must choose an explicit stable namespace. No storage or embed authority is inferred from a visual component: `embedProviders` defaults to empty. The host may explicitly select `['youtube','vimeo']`; arbitrary iframe markup and URLs are unsupported.

`vict.media.asset-library` supplies native owner file upload plus media archive import/export and selection. Bind its string `selectedAsset` output to the source state of another media component. Canonical source retains `asset:sha256:<digest>` identities; bytes stay outside the UI document. Reopening on the same origin/namespace resolves those bytes. To move to another browser/origin, export the media archive and import it with the source. A browser-local reference alone is not a portable asset bundle. Do not remove stored assets still needed by authored references. Imports validate all archive entries/digests before beginning writes; a host failure is reported and a digest-addressed retry is safe.

Each asset is limited to 64 MiB, each archive to 100 entries and 64 MiB combined. Images PNG/JPEG/GIF/WebP/AVIF, a deliberately inert SVG subset, MP4/WebM/Ogg video and WebVTT captions are supported inputs. Codec loading/playback remains browser-dependent. HTTP(S) supplied media URLs load directly in the consuming browser and may fail due network/CORS/host policy. No implicit remote fetch/search/generation/upload service or paid provider is used.

The supplied icon registry is a deliberately bounded manifest from pinned `@lucide/svelte@1.27.0` (ISC), with `pack/name/revision`, semantic tags and paginated search. `createIconRegistry` accepts application custom packs, whose custom entries have provenance/license and validated vector data. `importCustomIconPack` parses `vict.icon-pack@1`; register entries before rendering and preserve that manifest with the consumer. A custom authored icon may instead carry editable `data` or a managed SVG `source`, which survives normal document save and asset bundle replay. Size/currentColor/stroke width are controllable; multicolour vector fills are retained. An icon does not create an action: use it in a real labelled button/menu/node slot and preserve keyboard behavior.

Editable vector data is JSON with `schema:'vict.vector@1'`, `viewBox:'0 0 24 24'` and `nodes:[{tag:'path',attributes:{d:'M2 2L22 22',stroke:'currentColor'}}]`. Supported tags are paths, rectangles/circles/ellipses/lines/polylines/polygons, groups, definitions, gradients/stops, clips and masks. Geometry is validated, IDs/references are scoped per rendered occurrence, and raw HTML/SVG insertion, scripts, event handlers, foreignObject, external references and CSS are refused. Managed SVG import uses the same subset; it does not promise arbitrary SVG fidelity. Referenced immutable artwork and editable geometry are distinct choices.

Actual image loading, video playback/audio/captions, remote embed availability and device behavior require real browser evidence. A rendered poster or source declaration does not prove them. Cross-origin embed pixels are commonly unavailable to DOM screenshot tools. Report those limits rather than inventing observation or playback success.
