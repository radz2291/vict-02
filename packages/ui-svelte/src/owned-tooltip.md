# Application-owned tooltip

`OwnedTooltip` is shared coded-consumer infrastructure, not a new serialized component identity. The existing catalog Tooltip and AI MessageAction reuse it when canonical presentation or an application portal context establishes owned intent. Their unowned/document-scoped composition retains the existing public Bits Tooltip path. Descriptor revisions, props, outputs and compatibility pins do not change.

Supply a `trigger` snippet that forwards its supplied attributes onto the actual shared button/trigger element. The component resolves the actual owner through the canonical source root or application viewport; an explicit owner must contain the trigger in the same document. No application-owned tooltip falls back to a global body portal while owner resolution is pending. A supplied portal target must belong to that owner; otherwise the owner is the outlet. `scopeClass`, actual content attributes/styles and existing semantic tokens follow the portal.

The tooltip's stable ID is added to the actual trigger's current `aria-describedby` tokens. Closing or disposal removes only that ID, preserving other descriptions, including host updates while the tooltip is open. Content has `role="tooltip"`. It is descriptive content; use a popover or menu for independently interactive content. No autofocus, focus trap or focus restoration occurs.

Pointer hover uses the configured bounded delay; keyboard focus opens immediately. A brief close corridor permits moving from the trigger to the visible description without disappearing underneath the pointer. Escape dismisses only through the shared actual-owner layer hub; keyboard events from sibling/nested applications are not consumed. Activation dismisses the hint without cancelling the underlying action. Disabled, hidden, inert or detached sources cannot leave visible content; source visibility gates the DOM independently of a retained controlled `open` request.

The component uses the public Bits Portal utility for mounting and the shared public Floating UI positioning helper. It does not use private Bits state, document-wide input layers, a component-specific keyboard bypass, or body scroll/text-selection changes. Shared layer arbitration permits nested menus/dialogs to handle their own keys; tooltip callbacks return continuation for non-Escape keys. Existing AI Rhea button/content recipes and catalog trigger/content presentation remain in their respective wrappers.

Bind `open` and `onOpenChange` when the host needs controlled disclosure state. This is presentation state only; showing a tooltip grants no application execution authority. Native browser geometry, assistive-technology announcements, touch/device behavior and actual-agent output remain separate verification obligations while browser access is denied.
