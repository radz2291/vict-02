# Shared application-owned popup infrastructure

The owner-approved popup mode shares one owner-local listener and layer authority for dialogs, menus and tooltips. It does not patch Bits UI or change serialized authoring identities. Standard document-scoped composition remains a separate compatible mode.

`resolveOwnedPopupOwner(source, ownerId?)` resolves the source's application viewport, including its sibling portal outlet. Without that viewport, a standalone authored host uses its actual canonical `data-ui-owner-root`. An expected canonical owner mismatch refuses resolution; body is never guessed as an owned application. A portal target must remain inside the resolved owner/document. Source owner IDs further isolate different canonical documents sharing one physical viewport.

`registerOwnedPopupLayer` registers actual owner/panel/trigger references and a kind. It returns `isTop`, `owns`, `contains`, `dispose`, captured focus-return targets and ancestors. Input eligibility excludes disconnected, hidden or inert sources/panels even if a controlled close request is ignored. Menus/tooltips also require an enabled launcher; dialogs follow their visible content and remain operable when their launcher becomes disabled or hidden. `contains` admits exact live trigger/occurrence/ARIA-linked popup branches; `owns` describes the larger application boundary. Neither grants authority to a different nested application. `isOwnedPopupSourceTarget` supplies the same source-identity boundary for imperative focus-return checks before a layer exists or after it closes.

Keyboard, focus, pointer-down and click listeners attach to the owner element. The hub dispatches from the highest relevant layer down. A handler returns `continue` for unhandled events; an absent handler also continues. Returning nothing handles the event, and `defaultPrevented` stops further handling. A non-modal tooltip or menu must allow relevant focus/Tab continuation so an enclosing dialog remains modal within its own application.

Callbacks receive a second `{target}` context. Normally this is the real event target. When a menu Tab close synchronously removes that target, continuation can use an actual live trigger/ancestor return anchor after verifying the same ownership. This does not mutate an Event or synthesize another keyboard event. `isTopForRestore` is only a cleanup check: an already removed panel may restore focus if no other live higher layer exists. Restoration still needs the document's active iframe focus chain and actual prior focus containment; it is not permission to reclaim focus from another application.

`observeOwnedPopupSource` watches the actual source/owner ancestor chain and its realm's resize event. A read-only document membership observer rechecks only captured source references after detach/reinsertion; it never discovers or grants ownership to arbitrary popups. It reports hide, inert, disclosure, style/class visibility changes, detach and reparenting. An optional fifth `{excludeDisabled:true}` policy also reports disabled launchers for menus/tooltips; generic visual visibility does not treat disabled as hidden. `aria-hidden` alone is deliberately not visual removal, preserving the existing CatalogPortal policy for document modals. The optional fourth callback reports availability changes independently of the controlled open value. All observers/listeners have explicit cleanup.

`positionOwnedPopup` uses the public, directly declared `@floating-ui/dom@1.8.0` package for anchor/point positioning, clipping, flip, shift and auto-update. It fences stale asynchronous results and stops all update hooks. It changes only popup geometry, preserving authored style properties and restoring its own geometry on cleanup if those values have not since been changed by the host. A panel-style observer reapplies positioning when canonical dynamic style updates replace the entire attribute, retaining new binding variables and other authored declarations. `data-owned-popup-position` distinguishes pending, ready and unavailable geometry. No source DOM mutation or private component selectors are used.

Offline tests support only their stated behavior. Native browser geometry, iframe focus, capture, touch and actual Studio-agent proof remain separate checks. The saved browser-origin denial does not authorize another access attempt.
